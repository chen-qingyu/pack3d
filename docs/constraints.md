# 约束条件

求解器搜索时实时检查的硬约束。

## 1. 边界约束

箱子必须完全包含在容器边界内，三个维度（X, Y, Z）各自独立检查。

### 1.2 重叠约束

同一容器内的任意两个箱子不能有空间交集。

### 1.3 重量约束

每个容器内所有箱子的总重量不能超过该容器类型的 `max_weight`。未配置 `max_weight` 则跳过。

### 1.4 支撑率约束

箱子放置在 Z 高度 > 0 时，其底面（XY 平面）必须被下方箱子或容器底板支撑足够的比例。`support_rate = 0` 表示跳过此检查。

### 1.5 路线顺序约束（装货顺序）

路线定义了平台在 X 轴上的相对位置约束，门在 X 最大侧，货物从门装入。

设路线为 `[P₀, P₁, ..., Pₙ]`，则先装的平台在深处，后装的平台在近门处。
任意两个平台 `Pᵢ`（先装）、`Pⱼ`（后装），`i < j`，在同一个容器内满足：

- `Pⱼ`（后装）的箱子不得比 `Pᵢ`（先装）的箱子更靠里（X 更小）
- `Pᵢ`（先装）的箱子不得比 `Pⱼ`（后装）的箱子更靠近门（X 更大）

允许并列（相同 X 范围、不同 Y）和堆叠（相同 X 范围、不同 Z）。

### 1.6 平台数量限制

单个容器内最多允许 `platform_limit` 个不同的平台。平台已存在于此容器中时不受此限制。

### 1.7 发标数量限制（启发式）

`tender_limit` 限制同一个 `group` 的箱子最多能分散到几个容器中。

- 当一个 group 已触及 `tender_limit` 个容器，且仍有剩余箱子未放置时：
  - 尝试将剩余箱子放入已打开的容器中
  - 若某个箱子在所有已打开容器中均无合适位置 -> 判定为不可行（`status: "blocked"`）

这是启发式判断而非严格证明，用于快速检测明显不可行的分支。

## 2. 时间限制

`time_limit` 为软限制。超过时限后求解器停止搜索，返回当前最优结果：

- 已全装完 -> `status: "complete"`
- 未全装完 -> `status: "timeout"`

## 3. 约束与目标的关系

约束是必须满足的硬条件，目标函数在可行解空间中择优：

| 目标键                | 含义                                         | 方向     |
| --------------------- | -------------------------------------------- | -------- |
| `min_container_count` | 使用的容器数                                 | 越小越好 |
| `min_platform_split`  | 平台拆分总次数（每个平台都在一个容器中为 0） | 越小越好 |
| `max_volume_rate`     | 各容器平均体积利用率（0~1）                  | 越大越好 |
| `min_group_split`     | 组拆分总次数（每个组都在一个容器中为 0）     | 越小越好 |

目标固定不可配置。比较为字典序，只有优先级更高的维度打平时才看下一维。
