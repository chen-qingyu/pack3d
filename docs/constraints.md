# 约束条件

求解器搜索时实时检查的硬约束。目标是固定字典序（见 [architecture.md](architecture.md) §1.1），约束在可行解空间中择优。

## 1. 硬约束

### 1.1 边界约束

箱子必须完全包含在容器边界内，三个维度（X, Y, Z）各自独立检查。

### 1.2 重叠约束

同一容器内的任意两个箱子不能有空间交集。

### 1.3 重量约束

每个容器内所有箱子的总重量不能超过该容器类型的 `payload`。未配置 `payload` 则跳过。

### 1.4 支撑率约束

箱子放置在 Z 高度 > 0 时，其底面（XY 平面）必须被下方箱子或容器底板支撑足够的比例。`support_rate = 0` 表示跳过此检查。

### 1.5 路线顺序约束（装卸货通道）

路线定义了站点（配送停靠点）在 X 轴上的相对位置约束，门在 X 最大侧，货物沿 X 方向装卸。

设路线为 `[P₀, P₁, ..., Pₙ]`，表示卸货顺序（配送顺序）。先卸的站点在近门处（X 大），后卸的站点在深处（X 小）。装货顺序与卸货相反：先装（最深处）的货最后卸，后装（近门处）的货最先卸。
约束判断基于逐箱比较，而非站点整体 X 区间：

- 若两箱 Y 和 Z 均重叠，则路线顺序靠前的箱子（`Pᵢ`，`i < j`）必须完全在靠后的箱子（`Pⱼ`）的 X 外侧（近门），即 `Pᵢ.x ≥ Pⱼ.x + Pⱼ.dx`。
- 若两箱 X 和 Y 均重叠，则后卸站点 `Pⱼ` 不能直接叠压在先卸站点 `Pᵢ` 上方，即 `Pⱼ.z ≠ Pᵢ.z + Pᵢ.dz`（两箱之间不得有直接支撑关系）。Z 方向有间隙（`Pⱼ.z > Pᵢ.z + Pᵢ.dz`）则不受此限制。

两项规则独立：Y/Z 分隔允许 X 交错，X/Y 分隔允许 Z 交错。只有对应轴对同时重叠时，才施加该轴顺序约束。

### 1.6 站点数量限制

单个容器内最多允许 `platform_limit` 个不同的站点。站点已存在于此容器中时不受此限制。

### 1.7 运输委托容器数限制（tender_limit）

**tender（运输委托）** 定义：同一运输委托的货物共享 `group`（一票委托可含多个 group），在存在 `group` 的情况下，容器按共享 group 连通，每个连通分量即一个 tender。例如容器 A{g1,g2}、B{g2,g3}、C{g3,g4} 经 g2/g3 连通构成一个 tender，容器 D{g5} 是另一个 tender。

`tender_limit` 限制**每个运输委托（tender，连通分量）最多包含的容器数**。启用它要求有效箱子配置 `group`（`group` 可按箱型级或箱子级三选一提供；预校验强制：配置 `tender_limit` 但无任何有效 `group` 报 `invalid`，否则无 group 时该约束静默失效）。

求解时逐箱判断：把箱子放入容器 C 时，若该箱的 `group` 会使 C 所属的连通分量超过 `tender_limit` 个容器，则拒绝放入（该箱保持未装箱）。四个算法（GEP/GLC/RGS/BSG）在单容器填充时均执行此检查；后处理（站点合并、换小容器）同样遵守。

- 因该约束无法放入的箱子留在未装箱列表，`status` 为 `"partial"`。
- 这是硬约束：任何输出方案的每个 tender 分量都不超过 `tender_limit` 个容器。
- 输出中每个容器带 `tender` 字段（1-based 序号），即其所属分量的编号；无 group 的容器为 `null`。

### 1.8 堆码层数约束（max_stack，箱型字段）

任一箱型声明了 `max_stack`（非空）即启用。可配置为标量（全部朝向）或数组（与 `allowed_orientations` 对齐）。

**同箱型连续堆叠**：`max_stack` 限制的是**同箱型、连续相邻叠放**的层数（"这一箱型能叠 N 层高"，衡量同规格箱的抗压能力），**异型箱之间不互相计数**。每个已放置箱记录 `same_run`（本箱所在同型连续 run 的层数，含自身）与 `stack_level`（所在堆柱层号，地板层 = 1）。放置新箱 B（箱型 T，朝向 O）时：

- `B.stack_level = max(直接支撑箱.stack_level) + 1`（无支撑 -> 1）。
- `B.same_run = max(同型直接支撑.same_run) + 1`；无同型直接支撑 = 1。
- 校验：**同型 run 高度 `run = B.same_run` 须 ≤ run 内每个同型箱各自朝向的 `max_stack_for(其朝向)`**（B 自身及其正下方同型连续链上的每个箱）。不同箱型之间不互相计数：例如异型箱压在某箱型上，不增加该箱型的 run。

放置成功后 `B` 的份额沿支撑链向下累加到每个链上箱的 `cum_load`（max_load 整柱累计，见 §1.9）；`B.same_run` 按上式赋定。直接支撑箱 = 底面贴合（`S.top == B.bottom`）且投影相交（面积 > 0）。

**同层并排不增 run**：多个同型箱在支撑箱顶面**同一高度**并排摆放时，各自 `same_run = 支撑箱.same_run + 1`，不会因并排而叠加（例如底座 + 两个并排上层箱，每个上层箱 run = 2，底座 run 保持 = 1）。

**示例（跨不同高度支撑，同型 run）**：

- 弱箱 S1：100×100×100，`max_stack: 2`，在地板（层号 1，顶面 z=100）；
- 强柱：三只薄箱 100×100 高 33/33/34 叠成层号 1/2/3，顶箱 S2 顶面 z=100，`max_stack: 5`；
- 大箱 B：200×100×50，底 z=100，左半搭 S1、右半搭 S2，B 为强箱型。

B 与 S2 同型，`B.same_run = S2.same_run(3) + 1 = 4 ≤ 5` ✓；S1 为异型，不因 B 压上而增加 weak 的 run（`S1.same_run` 仍 = 1）→ 放行。若 B 为与 S1 同型的弱箱且 `S1.max_stack: 1`，则 `B.same_run = 2 > 1` → 拒绝。

> 预校验强制：声明 `max_stack` 必须**同朝向配置 `max_load`**（否则同型堆满后异型箱压上无承压兜底，报 `invalid`），且 `support_rate > 0`（否则悬空箱可绕过堆码/承重限制）。

### 1.9 单箱承重上限约束（max_load，箱型字段）

任一箱型声明了 `max_load`（非空）即启用。可配置为标量（全部朝向）或数组（与 `allowed_orientations` 对齐）。启用时要求有**重量信息**（箱型级 `box_types.weight` 或箱子级，输入重量三选一规则见 `docs/input.md` 预校验）。

两层判定，均为**沿支撑链**（直接支撑 + 传递支撑）传播：

**A. 面积分摊（A3，直接支撑逐对）**——按面积重叠比例分配下方箱的承重容量：

$$\text{份额}(B \to S) = w \times \frac{A_{B,S}}{\sum_i A_{B,S_i}}\qquad \text{分配}(S) = \text{max\_load}(S) \times \frac{A_{B,S}}{A_{\text{footprint}}(S)}$$

要求每个直接支撑箱 S（声明了 `max_load`）：$\text{份额}(B \to S) \le \text{分配}(S)$。

**B. 整柱累计（D，链上累计）**——底层箱承受其上一整柱（含传递）的重量：

$$\text{cum\_load}(X) + \sum_{\text{流经 X 的份额}} \le X.\text{max\_load}$$

放置成功后，B 的份额沿支撑链向下累加到每个链上箱的 `cum_load`；`B.cum_load = 0`。悬空部分不计入分摊（分母 = 受支撑面积）。

**示例（A，单支撑）**：upper 10×10×10 重 5 全压在 lower 20×20×10（`max_load: 10`）上，重叠面积 100，占比 100/400 = 1/4 → 分配 = 10×1/4 = 2.5，5 > 2.5 → 违反承重。

**示例（A，多支撑）**：B 200×100 重 60 各占 S1、S2（均 100×100、`max_load: 50`）一半：份额各 30，分配各 50 → 放行（物理各承 ~30 ≤ 50）。若 S1 `max_load: 5`、S2 `max_load: 95`：对 S1 份额 30 > 分配 5 → 拒绝（强箱不兜底弱箱）。

**示例（D，整柱累计）**：柱高 3 每箱重 5，底层 `max_load: 7`：中层压上时底层累计 5 ≤ 7 放行；顶层压上时底层累计 5+5 = 10 > 7 → 拒绝（即使顶层只直接压在中层上）。

> 与 `max_stack` 相同，承重检查沿支撑链传播；`support_rate > 0` 是物理有效前提（预校验强制，同 `max_stack`）。

### 1.10 重不压轻约束（heavy_not_on_light，约束级开关）

`constraints.heavy_not_on_light: true` 启用（默认 false）。启用时要求有**重量信息**（复用输入重量三选一规则，预校验强制）与 `support_rate > 0`（悬空箱无直接支撑，可绕过比较）。

**规则**：放置新箱 B 时，对**每个直接支撑箱 S**，要求

$$\text{weight}(B) \le \text{weight}(S)$$

即上方箱重量不得超过任一直接支撑箱重量（重量相等允许）。只查**直接支撑**（相邻层）：S 与更下层的比较在 S 放置时已检查，无需沿支撑链传播。

**示例**：重箱 30kg 压轻箱 10kg → 拒绝；轻箱 10kg 压重箱 30kg、或等重 20kg 压 20kg → 放行。

> 与 `max_stack`/`max_load` 正交：后两者是"容量"（能承多少），本约束是"顺序"（谁在上谁在下）。"指定底层/顶层"（如易碎置顶）可用本约束 + 重量表达，或与 `max_stack: 1` 组合。

### 1.11 障碍物约束（obstacles，容器类型字段）

容器类型可声明 `obstacles`（轴对齐长方体，如门框包边、台阶、轮拱凸起），所有该类型实例共享。障碍物为**实体**，两条硬规则：

- **禁入**：箱子不得与任何障碍物空间相交（面贴面允许）。
- **顶面等价地板**：箱子底面贴合障碍物顶面时，该面积计入支撑率检查的支撑面；放在障碍物顶上的箱子无直接支撑箱，堆码层号 `stack_level = 1`（开新柱），障碍物自身无承重上限。

体积口径：障碍物计入 `volume_rate` 分母（可用容积定义见 [output.md](output.md)）。

预校验（违反 -> `invalid`）：障碍物完全在容器内、障碍物互不重叠、`existing_containers` 已有放置与障碍物不重叠、障碍物不侵入斜面楔形禁区（面贴面允许，见 1.12）。

实现：共享 `check_obstacle`（相交）与 `check_support`（顶面支撑）为四个算法统一兜底；各算法的候选点/空间雕刻策略见 [algorithms.md](algorithms.md)。

### 1.12 斜面约束（facets，容器类型字段）

容器类型可声明 `facets`（斜切平面，如航空箱顶部斜切角），所有该类型实例共享。每个斜面用**恰好两个带符号轴名截距**描述（缺失轴 = 斜面平行贯穿的轴）：`+` 从该轴 min 侧向内进深、`-` 从 max 侧向内。

- **禁入**：斜面切掉角附近**楔形禁区**（凸半空间），箱子不得侵入（面贴面允许）。
- **不参与支撑**：斜面是斜坡，`support_rate`/`max_stack`/`max_load` 均不与其交互。
- **体积口径**：斜面计入 `volume_rate` 分母（可用容积定义见 [output.md](output.md)）；楔形占的空间已从分母扣除，可用空间装满即 100%。
- 斜面之间允许重叠（独立禁区，重叠只是更禁）；障碍物不得侵入斜面楔形禁区（面贴面允许，见 1.11）。

预校验（违反 -> `invalid`）：恰好两个非零截距、`1 <= |截距| <= 容器该轴尺寸`、`existing_containers` 已有放置不侵入斜面禁区、障碍物不侵入斜面禁区（见 1.11）。

实现：共享 `check_facet`（箱子极角点 vs 平面单次点积）为四个算法统一兜底。GLC/BSG 默认不做阶梯雕刻（阶梯碎片会切碎空间栈/残余空间、降低装载），楔形禁区分别由 `check_block_feasible` / `can_place_block` 的逐箱 `check_facet` 兜底（过挖为 0）。**例外（禁区覆盖原点）**：某斜面两截距均为正（贴原点角）时，GEP/RGS 用地板扫描补首个可用起点、GLC/BSG 对贴角楔形做阶梯雕刻——否则原点不可用会导致零装载。
