# 约束条件

求解器搜索时实时检查的硬约束。

## 1. 布局与物理约束

### 1.1 边界约束

箱子必须完全包含在容器边界内，三个维度（X, Y, Z）各自独立检查。

### 1.2 重叠约束

同一容器内的任意两个箱子不能有空间交集。

### 1.3 重量约束

每个容器内所有箱子的总重量不能超过该容器类型的 `max_weight`。未配置 `max_weight` 则跳过。

### 1.4 支撑率约束

箱子放置在 Z 高度 > 0 时，其底面（XY 平面）必须被下方箱子或容器底板支撑足够的比例。`support_rate = 0` 表示跳过此检查。

### 1.5 路线顺序约束（装卸货通道）

路线定义了平台在 X 轴上的相对位置约束，门在 X 最大侧，货物沿 X 方向装卸。

设路线为 `[P₀, P₁, ..., Pₙ]`，表示卸货顺序（配送顺序）。先卸的平台在近门处（X 大），后卸的平台在深处（X 小）。装货顺序与卸货相反：先装（最深处）的货最后卸，后装（近门处）的货最先卸。
约束判断基于逐箱比较，而非平台整体 X 区间：

- 若两箱 Y 和 Z 均重叠，则路线顺序靠前的箱子（`Pᵢ`，`i < j`）必须完全在靠后的箱子（`Pⱼ`）的 X 外侧（近门），即 `Pᵢ.x ≥ Pⱼ.x + Pⱼ.dx`。
- 若两箱 X 和 Y 均重叠，则后卸平台 `Pⱼ` 不能直接叠压在先卸平台 `Pᵢ` 上方，即 `Pⱼ.z ≠ Pᵢ.z + Pᵢ.dz`（两箱之间不得有直接支撑关系）。Z 方向有间隙（`Pⱼ.z > Pᵢ.z + Pᵢ.dz`）则不受此限制。

两项规则独立：Y/Z 分隔允许 X 交错，X/Y 分隔允许 Z 交错。只有对应轴对同时重叠时，才施加该轴顺序约束。

### 1.6 平台数量限制

单个容器内最多允许 `platform_limit` 个不同的平台。平台已存在于此容器中时不受此限制。

### 1.7 发标数量限制（tender_limit）

**tender** 定义：在存在 `group` 的情况下，容器按共享 group 连通，每个连通分量即一个 tender。例如容器 A{g1,g2}、B{g2,g3}、C{g3,g4} 经 g2/g3 连通构成一个 tender，容器 D{g5} 是另一个 tender。

`tender_limit` 限制**每个 tender（连通分量）最多包含的容器数**。

求解时逐箱判断：把箱子放入容器 C 时，若该箱的 `group` 会使 C 所属的连通分量超过 `tender_limit` 个容器，则拒绝放入（该箱保持未装箱）。四个算法（GEP/GLC/RGS/BSG）在单容器填充时均执行此检查；后处理（平台合并、换小容器）同样遵守。

- 因该约束无法放入的箱子留在未装箱列表，`status` 为 `"partial"`。
- 这是硬约束：任何输出方案的每个 tender 分量都不超过 `tender_limit` 个容器。
- 输出中每个容器带 `tender` 字段（1-based 序号），即其所属分量的编号；无 group 的容器为 `null`。

### 1.8 堆码层数约束（max_stack，箱型字段）

任一箱型声明了 `max_stack`（非空）即启用。可配置为标量（全部朝向）或数组（与 `allowed_orientations` 对齐）。

层号模型：每个已放置箱记录 `stack_level`（所在堆柱层号，地板层 = 1）。放置新箱 B 时：

- `B.stack_level = max(直接支撑箱.stack_level) + 1`（无支撑 → 1）。
- 对**每个直接支撑箱 S**，要求 `B.stack_level ≤ S.max_stack_for(S.orientation)`。

直接支撑箱 = 底面贴合（`S.top == B.bottom`）且投影相交（面积 > 0）。异构柱高受"最弱箱"限制；"限堆 N 层"= 柱含自身 N 层；同层并排不增层。

> 注意：`max_stack` 只约束有直接支撑关系的箱子。当 `support_rate = 0` 时求解器允许悬空放置，悬空箱不计入任何柱，可能绕过堆码限制；如需物理合理的堆叠，应同时开启 `support_rate`。

### 1.9 单箱承重上限约束（max_load，箱型字段）

任一箱型声明了 `max_load`（非空）即启用。可配置为标量（全部朝向）或数组（与 `allowed_orientations` 对齐）。启用时要求**所有箱子都带重量**。

面积加权分摊（分母 = 受支撑面积，悬空不计）：

$$\text{增量}(S) = w \times \frac{A_S}{\sum_i A_i}$$

放置新箱 B（重 w）时，对**每个直接支撑箱 S**：

- 若 S 在该朝向上声明了 `max_load`，要求 `S.supported_load + 增量(S) ≤ S.max_load_for(S.orientation)`。
- 放置成功后：每个直接支撑箱 `S.supported_load += 增量(S)`；B 自身 `supported_load = 0`。

只累加**直接**放置在 S 顶面的箱子（不沿柱递归累计）。单支撑半面积 + 半悬空 → 100% 重量给该支撑；两支撑各半（无悬空）→ 各 50%。

> 与 `max_stack` 相同，`max_load` 只约束有直接支撑的箱子；`support_rate = 0` 时悬空箱不产生承重，可能绕过限制。

### 1.10 障碍物约束（obstacles，容器类型字段）

容器类型可声明 `obstacles`（轴对齐长方体，如门框包边、台阶、轮拱凸起），所有该类型实例共享。障碍物为**实体**，两条硬规则：

- **禁入**：箱子不得与任何障碍物空间相交（面贴面允许）。
- **顶面等价地板**：箱子底面贴合障碍物顶面时，该面积计入支撑率检查的支撑面；放在障碍物顶上的箱子无直接支撑箱，堆码层号 `stack_level = 1`（开新柱），障碍物自身无承重上限。

体积口径：`volume_rate = 装箱体积 / 可用容积`，可用容积 = 物理总容积 − 障碍物体积 − 斜面楔形体积；目标 v3 `max_volume_rate` 与输出同口径。

预校验（违反 → `invalid`）：障碍物完全在容器内、障碍物互不重叠、`existing_containers` 已有放置与障碍物不重叠。

实现：共享 `check_obstacle`（相交）与 `check_support`（顶面支撑）为四个算法统一兜底；GEP/RGS 在极点集合初始化时加入每个障碍物 8 角点，GLC/BSG 把障碍物从初始空间/残差 cover 中挖掉（6-slab 完整分解）。

### 1.11 斜面约束（facets，容器类型字段）

容器类型可声明 `facets`（斜切平面，如航空箱顶部斜切角），所有该类型实例共享。每个斜面用**恰好两个带符号轴名截距**描述（缺失轴 = 斜面平行贯穿的轴）：`+` 从该轴 max 侧向内进深、`-` 从 min 侧向内。

- **禁入**：斜面切掉角附近**楔形禁区**（凸半空间），箱子不得侵入（面贴面允许）。
- **不参与支撑**：斜面是斜坡，`support_rate`/`max_stack`/`max_load` 均不与其交互。
- **体积口径**：`volume_rate = 装箱体积 / 可用容积`（可用容积 = 物理总容积 − 障碍物 − 斜面楔形）；楔形占的空间已从分母扣除，可用空间装满即 100%。
- 斜面之间允许重叠（独立禁区，重叠只是更禁）；与障碍物相互独立、无交叉校验。

预校验（违反 → `invalid`）：恰好两个非零截距、`1 <= |截距| <= 容器该轴尺寸`、`existing_containers` 已有放置不侵入斜面禁区。

实现：共享 `check_facet`（箱子极角点 vs 平面单次点积）为四个算法统一兜底；GLC/BSG 把斜面楔形从初始空间/残差 cover 中**N 步阶梯（N=2）挖掉**（只覆盖禁区、永不过挖安全台阶区）；GEP/RGS 纯检查。

## 2. 时间限制

`time_limit` 为软限制。超过时限后求解器停止搜索，返回当前最优结果：

- 已全装完 -> `status: "complete"`
- 未全装完 -> `status: "timeout"`

## 3. 约束与目标的关系

约束是必须满足的硬条件，目标函数在可行解空间中择优：

| 目标键                | 含义                                         | 方向     |
| --------------------- | -------------------------------------------- | -------- |
| `min_container_count` | 使用的容器数                                 | 越小越好 |
| `min_platform_split`  | 平台拆分总次数（每个平台都在一个容器中为 0） | 越小越好 |
| `max_volume_rate`     | 各容器平均体积利用率（0~1）                  | 越大越好 |
| `min_group_split`     | 组拆分总次数（每个组都在一个容器中为 0）     | 越小越好 |

目标固定不可配置。比较为字典序，只有优先级更高的维度打平时才看下一维。
