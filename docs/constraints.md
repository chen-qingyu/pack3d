# 约束条件

本文档说明 Hypercube 求解器涉及的全部约束条件，分两个阶段：

1. 输入预校验 — 解析 JSON 后的语义检查，拒绝明显无效的输入
2. 搜索期约束 — 求解器放置每个箱子时实时检查

## 坐标系

约定程序统一采用右手坐标系，定义如下：

- X 轴：长度，向右为正方向。
- Y 轴：宽度，向后为正方向。
- Z 轴：高度，向上为正方向。

---

## 1. 输入预校验

### 1.1 重复 ID

`container_types`、`box_types`、`boxes` 三组中各自的 `id` 必须唯一。

| 违规详情       | 说明              |
| -------------- | ----------------- |
| `duplicate_id` | 同组内出现重复 id |

### 1.2 未知箱子类型引用

每个 `box` 的 `box_type_id` 必须在 `box_types` 中存在。

| 违规详情           | 说明                   |
| ------------------ | ---------------------- |
| `unknown_box_type` | 引用了未定义的箱子类型 |

### 1.3 重量一致性

只要有一个箱子设了 `weight`，则：

- 所有箱子都必须有 `weight`
- 所有容器类型都必须有 `max_weight`

容器限重但箱子无重量也是允许的（此时整个重量约束不启用，所有重量相关检查跳过）。

| 违规详情              | 说明           |
| --------------------- | -------------- |
| `inconsistent_weight` | 重量信息不一致 |

### 1.4 路线一致性

设定了 `route` 时：

- 路线中不允许重复平台 ID
- 所有带有 `platform` 的箱子，其平台必须在路线中

| 违规详情                 | 说明                                   |
| ------------------------ | -------------------------------------- |
| `route_missing_platform` | 路线中有重复平台，或箱子平台不在路线中 |

---

## 2. 搜索期约束

### 2.1 边界约束

箱子在容器内部必须完全包含在容器边界内。

三个维度（X, Y, Z）各自独立检查。

| 违规详情                                         | 说明             |
| ------------------------------------------------ | ---------------- |
| `boundary` -> `box_exceeds_container_boundaries` | 箱子超出容器边界 |

### 2.2 重叠约束

同一容器内的任意两个箱子不能有空间交集。

| 违规详情                                   | 说明               |
| ------------------------------------------ | ------------------ |
| `overlap` -> `box_overlaps_existing_boxes` | 箱子与已有放置重叠 |

### 2.3 重量约束

每个容器内所有箱子的总重量不能超过该容器类型的 `max_weight`。

| 违规详情                                      | 说明     |
| --------------------------------------------- | -------- |
| `weight` -> `container_weight_limit_exceeded` | 容器超重 |

### 2.4 支撑率约束

箱子放置在 Z 高度 > 0 时，其底面（XY 平面）必须被下方箱子或容器底板支撑足够的比例，`support_rate = 0` 表示跳过此检查。

| 违规详情                                   | 说明             |
| ------------------------------------------ | ---------------- |
| `support` -> `insufficient_bottom_support` | 底部支撑面积不足 |

### 2.5 路线顺序约束（装货顺序）

路线定义了平台在 X 轴上的相对位置约束，门在 X 最大侧，货物从门装入。

设路线为 `[P₀, P₁, ..., Pₙ]`，则先装的平台在深处，后装的平台在近门处。
任意两个平台 `Pᵢ`（先装）、`Pⱼ`（后装），`i < j`，在同一个容器内满足：

- `Pⱼ`（后装）的箱子不得比 `Pᵢ`（先装）的箱子更靠里（X 更小）
- `Pᵢ`（先装）的箱子不得比 `Pⱼ`（后装）的箱子更靠近门（X 更大）

允许的场景：

- 并列 — 两个平台占据相同 X 范围但位于不同 Y
- 堆叠 — 两个平台占据相同 X 范围但位于不同 Z

| 违规详情                                 | 说明             |
| ---------------------------------------- | ---------------- |
| `route_order` -> `route_order_violation` | 违反路线顺序约束 |

### 2.6 平台数量限制

单个容器内最多允许 `platform_limit` 个不同的平台。

| 违规详情                                                    | 说明             |
| ----------------------------------------------------------- | ---------------- |
| `platform_limit` -> `container_would_exceed_platform_limit` | 容器内平台数超限 |

### 2.7 发标数量限制（启发式）

`tender_limit` 限制同一个 `group` 的箱子最多能分散到几个容器中。

- 当一个 group 已触及 `tender_limit` 个容器，且仍有剩余箱子未放置时：
  - 尝试将剩余箱子放入已打开的容器中
  - 若某个箱子在所有已打开容器中均无合适位置 -> 标记为不可行

这是一个启发式判断而非严格证明。它快速检测明显不可行的分支，避免浪费搜索时间。

| 失败原因       | 说明                                           |
| -------------- | ---------------------------------------------- |
| `tender_limit` | 超出组分散限制且无法在已打开容器中放置剩余箱子 |

---

## 3. 时间限制

`time_limit` 为求解器的软限制。超过时限后求解器停止搜索，返回当前找到的最优可行解（可能未全部装箱）。

超时不是约束违规，而是反映在 `success: false` + `reason: feasible`（有部分可行解）或 `reason: no_solution`（完全无解）。

---

## 4. 约束与目标的关系

约束是必须满足的硬条件，目标函数在可行解空间中择优：

| 目标键                | 含义                                     | 方向     |
| --------------------- | ---------------------------------------- | -------- |
| `min_container_count` | 使用的容器数                             | 越小越好 |
| `min_platform_count`  | 所有容器的平台总数（各容器平台数之和）   | 越小越好 |
| `max_volume_rate`     | 各容器平均体积利用率（0~1）              | 越大越好 |
| `min_group_split`     | 组拆分总次数（每个组都在一个容器中为 0） | 越小越好 |

目标按字典序比较，只有优先级更高的维度打平时才看下一维。
